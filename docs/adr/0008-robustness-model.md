# ADR 0008: Deferred destruction, context loss, and restore-failure policy
Status: accepted (Phase 6).

**Destroying a context that another thread holds.** Native contexts can only be released by the thread they are current on. The earlier rule (`tesseraDestroyContext` fails with `WRONG_THREAD`) made it impossible for a finalizer/`Cleaner` thread, which cannot know where the render thread is, to free anything. Now the handle is invalidated for everyone immediately and the object is parked on a pending list ("zombie"); the owner thread tears it down when it next releases the context (`tesseraMakeCurrent(NULL)`), switches to another context, or exits (a `thread_local` destructor). The teardown therefore always runs on the owning thread, which tests assert. A race where the owner releases between the ownership check and the parking is closed by re-checking after parking. `tesseraTerminate` drains the list. Cost: a destroyed context's native resources can outlive the call, for as long as the owner keeps it current.

**Context loss.** `tesseraGetResetStatus` wraps `glGetGraphicsResetStatus` (core/KHR/ARB/EXT spellings) and is only meaningful for contexts that were *granted* robust access and reset notification (checked against what the driver reports, not what was requested). Any non-`NONE` status makes the context permanently *lost*: `makeCurrent`, `swapBuffers` and `setSwapInterval` return `CONTEXT_LOST`, and asking again returns the same status (the driver going quiet does not heal it). A backend that learns of the loss natively (EGL's `EGL_CONTEXT_LOST`) reports `TESSERA_ERROR_CONTEXT_LOST` and the core marks the context the same way. Polling is the application's job; Tessera does not poll behind its back. Releasing a lost context always works. Not done: mapping Windows TDR / GPU hot-unplug to `CONTEXT_LOST` without robustness (no reliable native signal found in WGL/GLX).

**Share groups and recreation.** Contexts created with `shareWith` belong to one tracked group. `tesseraRecreateContext` builds a new context from the lost one's stored request and joins a surviving, non-lost member of its group (flag `TESSERA_RECREATE_SHARE_PRESERVED`); if none survives it starts an empty group and the application must re-upload. The old handle stays valid and is destroyed by the caller. Sharing with a lost context is refused (`CONTEXT_LOST`).

**When restoring the host's context fails.** Every backend saves and restores the caller's native current state around its work. If the restore itself fails (the host's context or surface died meanwhile), the one thing Tessera must not do is leave one of *its* contexts current on a thread that never asked for it. Policy: retry once where the failure can be transient (CGL), otherwise log and release, leaving the thread without a context. WGL already did this; CGL, GLX and EGL gained it after the fault-injection sweep exposed the gap.

**Strictness is checked against read-back, never against the request.** Every reported flag, size, version and profile comes from the driver; `contextSatisfies` (strict mode) now also covers reset notification, release behaviour and the colour/depth/stencil minimums; and the test suite verifies results with an independent oracle (`tests/robustness_common.hpp`) over a 192-combination matrix per backend.
