# ADR 0007: macOS backend over CGL, loaded with dlopen, drawable-less
Status: accepted (Phase 5), **unverified on real hardware** (see below).

**CGL, not NSOpenGL.** CGL is a plain C API with no AppKit dependency, no main-thread rule, and no need for `NSApplication`, so a CGL-only backend cannot interfere with AWT/JavaFX owning the application. NSOpenGLContext/NSView would add exactly the threading and run-loop concerns the library is built to avoid, for on-screen rendering Tessera does not do anywhere.

**No drawable.** CGL contexts can be current without any drawable; rendering is to framebuffer objects. Consequently there is no default framebuffer, `tesseraSwapBuffers` is a no-op, swap interval is `UNSUPPORTED`, and every context reports `surface = NONE`. Pbuffers (deprecated since 10.7) are not used.

**Loaded at run time.** `OpenGL.framework` is opened with `dlopen`, and the few CGL types, error codes and pixel-format attribute values are declared by hand (`cgl_types.hpp`), exactly like libEGL/libGL/libX11 elsewhere. The payoff is not only "no build dependencies": the backend contains no Apple headers and no Objective-C, so it compiles under MSVC and gcc with the project's warnings-as-errors flags, and it can be executed on any platform against a fake `OpenGL.framework` (`tests/fake_cgl.cpp`). `TESSERA_CGL_LIBRARY` selects the library.

**What macOS can express.** Two desktop contexts: legacy 2.1 compatibility, and core (3.2 up to 4.1, always forward-compatible). Core requests try the 4.1 profile, then 3.2, and a 3.0+ request is a core request even with profile "any". Not expressible, hence refused in strict mode and dropped in best-effort mode: ES (left to ANGLE/EGL), compatibility above 2.1, debug / robust access / no-error / flush control, and an sRGB default framebuffer. Shared objects require matching profiles, so a child follows its parent's and legacy/core cannot mix. A pixel format that exists only on an offline GPU is tried last, since allowing offline renderers can wake a discrete GPU on hybrid Macs.

**Verification gap (important).** There was no Mac while this was written. The control flow is verified against the fake (ASan/UBSan/TSan clean); the following are *assumptions about Apple's behaviour* and unchecked: the numeric constants, the colour-size convention (a heuristic derives per-channel bits), the forward-compatible bit on core contexts, pixel-format ranking, and what hosted macOS VMs provide. `tests/test_cgl.cpp` uses the same constants for an independent raw context, so the first real run exposes a wrong value immediately. Until it passes on a Mac, treat this backend as experimental.
